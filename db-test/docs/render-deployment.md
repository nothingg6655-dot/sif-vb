# Deploy the API to Render

The Supabase database and current data are already deployed. Render runs the
Node/Fastify API; Flutter uses the Render HTTPS origin in production builds.

## Publish the code changes first

The GitHub repository is `https://github.com/nothingg6655-dot/sif-vb`.
Its root is the local `Backennd/` folder, and the API directory within that
repository is `db-test/backend`. Commit/push the current backend configuration,
the public `backend/certs/supabase-ca.crt`, and `render.yaml` before deploying.
Do not commit `.env.render`, other credential files, or database backups.

## Render service settings

Create a **Web Service**, connect the repository, and choose:

- Branch: `main`
- Runtime: Node
- Root Directory: `db-test/backend`
- Region: Singapore, matching the Supabase region
- Build Command: `npm ci --include=dev && npm run build`
- Start Command: `npm start`
- Health Check Path: `/health`

Leave the pre-deploy command empty. Render supplies `PORT`; the server reads it.
TypeScript is a development dependency, so the build command explicitly installs
development dependencies even when `NODE_ENV=production`.

Alternatively, create a Render Blueprint from the repository's root `render.yaml`.
It sets the same commands and prompts for the read-only database password. Its
`ADMIN_API_KEY` is generated by Render. The blueprint defaults to the Free plan;
select a plan appropriate for the service's availability requirements.

## Environment variables

For a manually created service, open **Environment > Add from .env** and import
the private local `db-test/.env.render` file. This file was prepared with the
existing read-only database password and a generated admin key.

Required deployment values:

```dotenv
NODE_VERSION=24
NODE_ENV=production
HOST=0.0.0.0
PGHOST=aws-0-ap-southeast-1.pooler.supabase.com
PGPORT=5432
PGDATABASE=postgres
PGEXPECTED_DATABASE=postgres
PGUSER=sif_backend.pduxixfhejkslwafxplw
PGPASSWORD=<read-only password from the private .env.render file>
PGSSLMODE=verify-full
ADMIN_API_KEY=<generated value from the private .env.render file>
```

The prepared file also includes these runtime settings:

```dotenv
PGPOOL_MAX=5
PGCONNECT_TIMEOUT=30
PGSTATEMENT_TIMEOUT_MS=30000
APP_TIMEZONE=Asia/Kolkata
LOG_LEVEL=info
```

Do not copy the local `PGSSLROOTCERT=data/...` path into Render. The backend uses
its bundled Supabase public CA when no override is supplied. A custom certificate
can still be configured with `PGSSLROOTCERT` when needed.

Only the read-only role is required for Render's API. Keep ingestion/admin
credentials, `BACKEND_PGUSER`, `BACKEND_PGPASSWORD`, and `SIF_ENV_FILE` out of this
service's environment; `PGUSER`/`PGPASSWORD` above already identify the backend role.
No Supabase URL, anon key or service-role API key is required for this PostgreSQL
connection. Database and admin secrets must never be passed to Flutter.

## Verify the deployment

After Render reports the service Live, use the actual URL shown by Render:

```text
https://YOUR-SERVICE.onrender.com/health
https://YOUR-SERVICE.onrender.com/api/analytics/category-comparison
https://YOUR-SERVICE.onrender.com/api/analytics/monthly-heatmap?range=all
```

`/health` should return `{"status":"ok","database":"connected"}`.
The sync-status admin endpoint requires `Authorization: Bearer <ADMIN_API_KEY>`;
the public app must not contain that key.

## Flutter development and production

Run commands from `sif_research/`. Local development defaults to
`http://127.0.0.1:3000`. Production builds require an explicit public HTTPS API
origin, without `/api` or any path suffix. Debug defaults to development; release
defaults to production. Explicit `APP_ENV` flags make the intended mode clear.

```powershell
# Local Chrome development
flutter run -d chrome --dart-define=APP_ENV=development --dart-define=API_BASE_URL=http://127.0.0.1:3000

# Local Chrome preview using the deployed backend
flutter run -d chrome --dart-define=APP_ENV=production --dart-define=API_BASE_URL=https://YOUR-SERVICE.onrender.com

# Production web files: build/web
flutter build web --release --dart-define=APP_ENV=production --dart-define=API_BASE_URL=https://YOUR-SERVICE.onrender.com

# Production Android APK
flutter build apk --release --dart-define=APP_ENV=production --dart-define=API_BASE_URL=https://YOUR-SERVICE.onrender.com
```

For the Android emulator's local backend, use `http://10.0.2.2:3000` with
`APP_ENV=development`. A USB-connected physical phone can use localhost with the
existing `adb reverse tcp:3000 tcp:3000` workflow.

These values are compiled into the Flutter build; changing the Render hostname
requires rebuilding and redeploying the Flutter app. There is no production
hostname guessed or hardcoded in the source.

## Ongoing data updates

The Node web service serves API requests. It does not start the Python NAV,
factsheet, or benchmark ingestion jobs. Those continue to use the existing cloud
database configuration and require a separately deployed worker/cron service for
updates while the development computer is off. Do not run migrations or ingestion
as the web service's build/start command.
